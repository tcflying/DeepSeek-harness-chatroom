## 故障归因与证据

| 用户问题 | 确认的失效机制 | 修正 |
| --- | --- | --- |
| 常用界面没有登出 | 服务端已有 `/auth/logout`；旧入口仅在房间目录，原生设置中的账号组件没有接入 logout | 设置 → 群聊与账号顶部增加退出登录；不依赖选中房间；重复点击和失败有反馈 |
| 登出可能是假成功 | `ChatroomClientStore.logout` 原先在 finally 中无条件切换为未登录，服务端失败也清空视图；登录/登出没有清理全部管理缓存 | 成功才进入登录页；失败保留状态并支持重试；清理插件管理、授权视图、搜索、分支和转发缓存 |
| 角色权限不明 | 平台 `admin`、`super-admin`、配置白名单与群内 owner/admin 是不同判定，界面统一写“管理员” | 显示平台身份与群内身份、权限说明；保留历史 admin 兼容，但界面不再创建这种无额外授权的角色 |
| 非管理员看到过多配置 | 普通用户不能保存全局配置，但 automation overview 仍返回实际提示词/模型；AI overview 与实时广播也发送完整配置 | 普通成员隐藏插件全局设置卡；服务端返回空的受限字段；非管理者不再收到 AI 详细指令、模型路由或推理配置 |
| 撤销管理权后残留配置 | 实时广播没有按接收者权限投影；原客户端事件处理保留旧 canManage/models | 按当前群角色和有效超级管理员身份生成事件；群内角色变更立即推送；客户端清除被撤销的模型目录和管理入口 |
| 切换账号可能保留表单草稿 | 同一 React 表单实例跨账号复用，清理服务端缓存不等于清理本地输入状态 | 按当前账号重建设置内容，避免旧密码/提示词草稿留给下一账号 |

这些是确定性的界面接线、授权投影和状态生命周期缺口，不是网络闪断或模型响应速度问题。刷新/重启不会自动补上缺失的逻辑；本轮不以服务重启或 HTTP 200 作为根因证据。

## 权限口径

- 平台超级管理员：账号、登录方式、全局配置，以及群成员/AI 管理；不自动取得他人的私有会话。
- 设置白名单账号：全局配置授权，不等于平台用户管理或群管理授权。
- 历史平台 admin：不因名称自动增加权限；保留存量记录兼容。
- 群主/群管理员：本群成员、AI 配置和自动回复；只有群主分配群管理员。
- 群成员：聊天、@AI、已授权会话与个人账号。平台普通成员可以同时是某个群的群主或群管理员，两层权限不能混为一谈。

六位密码输入与原有服务端 6–128 位规则同时对齐；本轮没有更换任何人的实际密码。
