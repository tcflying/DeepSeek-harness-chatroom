# 反复连接中与管理面板遮挡：修复和证据

日期：2026-09-11，UTC+8。生产最终包 `1.5.0-codex.rc1.26`；本轮仅改聊天插件及其部署 overlay，不改 DSH 源码或其他插件。宿主 CLI `0.1.5-rc.1` / transport `0.1.5-rc.2` 的升级是另一个任务此前的操作。

## 故障归因及归因证据

### 已确认：插件在读取就绪时主动打断原生连接

`src/client/index.tsx` 旧逻辑在每次 `phase` 进入 `ready` 时无条件调用 `connection.reconnect()`，没有区分已有身份首次加载、同步恢复和真实登录变化。即使原生流正在正常建立，也会主动废弃该连接；手动重连后若 store 经过 loading/ready，还会再重连一次。

原内置浏览器两次读取有 `connection lost, retry #1`：13:23:36.221Z、13:35:47.689Z；后一次是有界同页重新进入，服务器紧接着在 13:35:48.680Z 记录刚建立 1107ms 的 native 对端结束并重新打开。这与旧 ready 回调的主动断链行为一致。前一次随后历史长时间加载，手动重连后恢复；不将所有旧记录都自动归因于这一次回调。

rc1.26 的 `native-identity-sync.ts` 只在登录/创建身份流程后或 participantId 确实变化时重建原生连接，同账号首次读取及只读恢复不再强制重连。身份切换/重新登录不会被优化跳过；手动重连仍保留。对应 4 个时序测试覆盖这些分支；最终原页冷进入与手动重连结果见 `RC126-iab-acceptance.json`。

最终 13:42:18.618Z 同页重新进入，至 13:44:33Z 原页已自行显示历史及缩略图，期间没有 `[connection]` 警告；服务端 13:42:25 的原生连接保持到第一次人工重连才关闭。这里记录的是观察时间，不把采样间隔说成加载耗时。通知/房间皆在线回执为 13:42:46.413Z，实际图片 GET 为 13:43:01.062Z。随后实点手动重连：13:48:24.102Z 只有一次 `connection lost`，另有 3 秒尚未 ready 的弱网警告，最终三层在线、历史与图片恢复，富文本草稿“重连验收草稿（未发送）”仍在；已清掉本次草稿，没有发送。公网仍存在慢请求，不声称秒开或从不出现等待。

### 已确认：安静的通知流需要 15 秒才完成握手

旧服务调用 `writeHead()` 后，没有立即写正文。Node 缓冲响应头，直到首个 15 秒心跳才真正送出。浏览器通知 EventSource 因此一直处于 CONNECTING；返回前台、重新打开读取连接时重复这个等待。总状态灯把原生会话、群消息、通知三层合并，不能从旧文案判断是哪一层。

同时探测的修前证据 `SSE-LIFECYCLE-1789129525776.json`：本机 3181 通知头 15010ms、中转 3185 通知头 15010ms、公网通知头 15417ms。三路都存在同一延迟，证明不是单凭 Cloudflare 日志猜测。

修复后立即发送命名心跳，携带流 ID / 心跳间隔。隔离宿主通知头 12ms；生产三路通知头分别 148ms、95ms、495ms。生产群消息头分别 170ms、144ms、8341ms，**公网仍有额外网络延迟，不能说所有请求都小于 1 秒**。六路连接各维持 185 秒，均由探针主动结束，收到至少 12 次心跳；服务端可通过流 ID 找到对应 close 及心跳计数。

修后证据：`SSE-LIFECYCLE-1789130945562.json`。这证明当前机制修复与有界存活，不证明永久不断线，也不能追溯每次用户历史断线。

### 已修：读取连接卡住后缺少有界恢复

客户端新增连接头 25 秒期限；正常命名心跳间隔 15 秒时，45 秒无消息/心跳即关闭旧流，复用已有有界退避重新建立 GET 读取。不会自动重发聊天、改图或视频等付费操作。关闭/隐藏界面会清除计时器和监听器。

服务端清理绑定实际 `ServerResponse.close/error` 和请求中断；不把已读取完毕的 GET 请求 `close` 误当成响应断开。断开、插件停止、鉴权失效都会一次性移除订阅和心跳/复核定时器。对应真实 HTTP 生命周期与虚拟时钟测试见 `tests/sse.test.ts`、`tests/read-stream-watch.test.ts`。

### 已确认并修复：管理层级与表单尺寸不正确

原 AI 成员、群管理是侧边面板，会受到宿主 Files 的层叠、裁剪影响。现为挂载到 body 的原生 `dialog.showModal()` 顶层弹窗，独立于其他侧栏；限制视口边距与高度、内容滚动、44px 关闭按钮、Esc/遮罩关闭、焦点返回入口。

实际截图复查还发现 AI“启用成员”把文案直接放在固定 38×22px 的开关外观容器中，文字溢到添加按钮。rc1.25 把标签与开关分离，补齐独立表单栅格、16px 控件字号、42px 控件高度、44px 启用标签区域；加载中不再误报空列表或没有管理权限。这是插件自身表单尺寸问题，不归咎于新宿主。

## 原生连接与探针路径边界

独立原生 WS 探针没有发送 RPC、消息、文件或生成请求。本机、中转和公网现有环境代理路径各存活 155 秒、各收到 10 次 ping，全部由探针关闭。证据 `NATIVE-ROUTE-1789132869493.json`。rc1.25 服务端与此次探测使用的 rc1.24 字节相同。

Node `ws` 默认连接路径在公网握手前出现 `ECONNRESET`，未 open、无 HTTP 状态；显式使用现有环境配置的 HTTPS Agent 后同域 926ms open 并持续上述 155 秒。只修正测试客户端路径，没有改用户代理/DNS/防火墙。这条命令行路径失败**不等同内置浏览器断线，也不是服务端已接通连接自行关闭**。

先前把 155 秒探测放入交付守卫时，守卫自身 120 秒命令期限终止了探针，在 13:11:56Z 造成两条测试连接结束（其中一条服务端记 socket-error / ECONNRESET）；这是验收进程被终止的记录，不隐去、不当作用户故障。后续长探针独立运行，守卫仅核验已完成证据和当前部署。
