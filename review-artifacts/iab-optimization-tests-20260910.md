## 窄屏失败的具体数据

测量高度均为 900 CSS px，检查的是实际设置弹窗及内部控件 getBoundingClientRect。

| 视口宽 | document.scrollWidth | 弹窗 x / width / right | AI 名称/职责/模型/添加按钮 x / right |
| --- | --- | --- | --- |
| 320 | 320 | 24 / 272 / 296 | 236 / 406 |
| 360 | 360 | 24 / 312 / 336 | 236 / 406 |
| 390 | 390 | 24 / 342.4 / 366.4 | 236 / 406 |
| 768 | 768 | 24 / 720 / 744 | 无超出视口的测量控件 |
| 1280 | 1280 | 240 / 800 / 1040 | 无超出视口的测量控件 |

复现：打开侧栏 → 设置 → 群聊与账号 → 390px。原生左侧设置导航仍占较大宽度，右侧内容被压窄，输入框和模型选择被裁切。**只检查 document.scrollWidth 会漏掉这个失败。** 已将数值和复现交给用户另行授权、正在负责手机/折叠屏优化的协作任务；本任务没有同时修改其样式文件或重启实例。

## 浏览器阻塞及故障归因

1. 页面控制台记录 `[connection] connection lost, retry #1`。这是连接中断证据，不足以解释所有 disabled 状态。
2. 启用 Network 观察、尝试刷新后，读取失败：`Timed out running CDP command "Runtime.evaluate" for tab 4`。
3. 继续读取事件失败：`Timed out running CDP command "Emulation.setFocusEmulationEnabled" for tab 4`。
4. 已有备用标签最初可读取 401 文本，刷新时 `Page.getFrameTree` 超时并导致工具会话重置。
5. 通过应用原生导航重新定位当前任务后，原标签仍在 focus 命令超时；新建同目标测试标签在 `Page.navigate` 超时。
6. 同期 shell 只读检查插件健康入口返回 HTTP 200 / `{"ready":true}`。该证据仅排除进程完全退出，不能证明所有 API/模型健康。
7. Codex 当日日志记录 `No ChatGPT browser route is available for browser session ...`、`reason=cdp-timeout`、`target closed while handling command`。日志位置：`C:\Users\datoo\AppData\Local\Codex\Logs\2026\09\10`。

故障归因：设置窄屏失败已有几何和截图实证；管理按钮禁用的底层原因未知。后续验收的直接阻塞是内置浏览器跨标签 CDP 控制超时及路由不可用；尚未确定其触发因素，也未证实它与插件前端行为存在因果关系。工具重置、重新导航与新标签未恢复，因此没有把反复重试算作自愈。

未继续原因：用户指定内置浏览器；该浏览器在原标签、备用标签和新标签均无法完成控制命令，已做上述有界恢复；另一个任务正拥有响应式修复文件，本任务不并发改写或替换被测实例。下一步：恢复该任务的内置浏览器路由/调试连接，先核对原测试消息与管理按钮状态，再依矩阵完成真实连续 @、取消、切房/账号和网络恢复；响应式新构建需单独确认安装哈希后复验，不能覆盖本旧构建的失败记录。
